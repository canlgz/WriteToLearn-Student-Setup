# 轉折升格手動測試對照表

對應 `src/TestbedSeed.gs` 的 4 條測試脈絡。種子下完之後,照下面對著 LINE 一條一條測。

---

## 步驟總覽

1. **清掉舊資料(擇一)**
   - 在 script.google.com editor 跑 `wipeAllOwnerData()`(較安全,走 bot 既有 lock)
   - 或 Drive web 直接刪 OWNER chat 資料夾下的 `embeddings.jsonl` / `contexts.jsonl` / `journeys.jsonl`(bot 下次讀會自動建空檔)
2. **種子四條測試脈絡**
   - editor 跑 `seedTransitionTestbed()`(~25 次 Gemini embed call,可接受)
   - console 會印每條的「期望轉折」
3. **LINE 上 `/journey`**:應該看到 0 條學習歷程 + 4 條候選歷程(都標 🌿 候選歷程·持續關注)
4. **逐條按「補一個轉折」**,依下方對照表輸入「正確補充文」或「離題補充文」,確認 bot 回應符合期望

## 已知會踩到的限制(這次測試不修,但你會看到)

1. **synthesize 凝聚 LLM 可能幻覺**:你寫「兩件事不相關」可能被凝聚成正面敘述。這是 Phase 1 cos 閘的盲點,要做修法 1+2(跳過 context-targeted 的 synthesize + 否定偵測)。先記得就行。
2. **markerGap 是 Phase 2 種好的,但目前 UI 沒顯示**:`buildTransitionSuppIntroBubble_` 還是四種轉折通通攤給你選。要做 Phase 3 才會「主動引導:這條最可能是 X 轉折,試試...」。現在預期 markerGap 的方式靠你看這份對照表。
3. **凝聚卡的「對齊使用者意圖」相當依賴使用者文字本身的明確度**——這次測試用的「正確補充文」都很明確,實機真實使用時不會這麼乾淨。
4. **升格只進不退**:測試完一條已升格的後,要再測就要 wipe + reseed,不能在同一條上重玩「補一個轉折」(它已經是 journey 不會再判)。
